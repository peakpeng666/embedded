# 潘多拉实验：证据、冲突和实现边界

## 资料是否就是这块板

资料是从正点原子官方下载中心的“潘多拉 IoT 开发板”入口取得，包含原厂 V3.4 原理图、V3.4 元件位置图、V2.4 历史资料、入门指南和完整开发指南。下载入口、提取码与本地文件见 `README.md`，文件 SHA-256 见 `official_sources.json`。

这比使用通用 STM32 最小系统图可靠：当前用到的 PD10/KEY0、PD9/KEY1、PE7/8/9、PA9/10、板载 DAP/USB-UART 都能对应厂商图。不过“来源正确”不等于“已测得实物 PCB 丝印版本”。本次没有摄像头顶标和 PCB 丝印照片，故没有将 V3.4 写成已直接读出的实物版本。

官方开发指南 PDF 第 18、23、27 页明确使用 STM32L496VET6、LQFP100、320 KB SRAM 和 512 KB Flash；第 52、65 页的 Keil 型号和代码宏也支持 L496。原理图 U3 却保留 STM32L475VET6 字样。重绘的型号依据是指南与当前工程。实板 SWD 读到的器件族 ID、Cortex-M4 和 512 KiB 容量提供相容性证据，但器件族 ID 不能独立区分全部 L47/L49 型号，不能把它说成芯片顶标鉴定。

## 原图不能照抄而不核验的细节

| 项目 | 经放大核对的事实 | 本次处理 |
| --- | --- | --- |
| VREF 连接 | 器件为 R13/10R；旁边文字却写 R18 | 按器件标注绘 R13=10Ω，保留冲突说明；没有声称实测 |
| C28、C29 | C28=104，C29=225 | 分别绘 100nF、2.2µF，没有颠倒 |
| 模拟电源 | R15=10R，C30=104，C31=10µF | 保留 VDDA 与 VREF+ 的独立支路 |
| 数字供电 | R17/R18 两个 0R 并联；C37–C41=104 | 没有把其中一个当成 VREF 电阻 |
| J1 排针 | DAP_RX/1、DAP_TX/2、UART1_RX/3、UART1_TX/4 | 连通配对 1–4、2–3；串口实测证明路径可用，未声称看到短接帽 |
| J2 | DAP 控制器自身调试接口 | 目标调试使用 T_JTMS、T_JTCK、RESET 网络 |
| Y3 | 8MHz 四焊盘无源晶体，2/4 接地 | 不误画成四脚有源振荡器；C35/C36=22pF |
| Y2、RGB、按键 | 原厂图没有足够的物理封装脚序信息 | 使用 IN/OUT、A/R/G/B、A/B 功能端；不捏造 PCB 焊盘号 |
| BOOT1 | 1=3.3V、3=GND；2 经 R14=10k 接 BOOT0 | 保留选择器，不假定当前帽位，也不修改选项字节 |

原生工程是现有开发板的实验相关电路摘绘。板上无线、传感器、显示等外围没有全部展开；U3 的全部 100 脚仍保留端点。未展开引脚不能标为“实板悬空”。未做 PCB 布局、封装匹配和完整生产 ERC，因而不是可直接制造的新板设计。

## 流程图与当前代码的对应关系

| 图中行为 | 实现依据 | 判断 |
| --- | --- | --- |
| 16MHz HSI、向量表偏移、低有效 RGB | `lab1/src/main.c` 的 `hardware_init()` | 先将 PE7/8/9 置高，再切输出，避免初始化点亮；外部晶体不是本例时钟依赖 |
| KEY0 每 5ms 查询 | `main()` 与 `LAB_POLL_MS` | 查询分支先更新 `last_poll=now`，没有给 PD10 配 EXTI |
| KEY1 双沿记录 | `EXTI9_5_IRQHandler()` | ISR 清标志、记录时间/电平并置 pending，不在 ISR 里等待或切 LED |
| 主循环处理 KEY1 | 原子复制 IRQ 邮箱、`lab_key1_edge()`、`lab_service_key1()` | 有真实 IRQ 边沿才能建立处理请求；不能用普通电平轮询冒充中断触发 |
| 20ms 消抖 | `lab_logic.c` 的两个按键服务函数 | 当前采样改变会重新计算稳定起点；按住只计一次有效按下 |
| 停止优先 | `lab_poll_key0()` 检查 `!lab->key1.stable` | 优先级基于已经消抖确认的 KEY1 状态；新出现的电平仍需消抖，并非硬件瞬时关断 |
| 松开停止键不自启 | `lab_service_key1()` 的 release 路径 | 释放只更新稳定状态；需新按 KEY0 才重新从红色开始 |
| 七色轮闪 | `lab_led_mask()` 的 14 项 blink 表 | 1/0/2/0/4/0/3/0/6/0/5/0/7/0；300ms 每帧，4.2s 一轮 |
| 灭帧和停止状态不同 | `lab_led_mask()` 与 `LAB_OFF` | COLOR 内的灭帧不会改变模式枚举；不能在流程图中把每次灭帧写成停止 |
| 非阻塞输出 | 帧时间推进与 `uart_service()` | 不使用 delay 等 300ms；串口 TX 环形缓冲和 RX 查询随主循环运行 |

停止响应需要稳定窗口和主循环服务。两键几乎同时按下时，不能把“稳定停止键优先”夸大为“原始电平一出现即零延迟灭灯”。本轮保留现有实现语义，没有为画图悄悄修改固件。

## 实际做过与没有做过

已经在 Keil 编译并实板烧录校验，完整 Flash 读回确认仅应用区两个 2KiB 页变化，前 64KiB 引导区不变；Keil/CubeIDE 的实板单步和变量观察、MobaXterm 的 COM3 状态查询均有实际录屏。CubeIDE 的 GNU 产物成功编译，但没有将它当成板上 Keil 固件的匹配符号。

本轮没有机械臂或相机，没有实际按实体按键的新增证据。录像中修改 `lab.mode` 是调试器写 RAM，不能说成实体 KEY0 操作。按键逻辑的既有六组主机测试通过，不能替代新的实物按键验证。

Proteus 运行的是本机既有 STM32F401 LCD 例程，只证明该仿真工程能工作，不证明潘多拉 L496 外围已经完成模型级仿真。嘉立创交付是静态原理图与流程图，也没有声称完成 L496 模型仿真。

## 可复核交付

`lceda/verification-results.json` 记录原生工程、应用保存副本、实际网表和 ST 引脚 XML 的 SHA-256。`verify_lceda_export.py` 对 EDA 导出的 25 个网络逐个比较完整成员集合，对 39 个器件标值和 100 个 MCU 脚号/脚名比较；未把“画面像电路”作为连线正确的充分证据。

`lceda/lceda-original-export.pdf` 保留应用直接导出的四页 PDF。最终 A3 版只做矢量文字轮廓转换与页面缩放，实际编辑入口始终是原生 JSON。后续任何修改都应重新从嘉立创导出、核对和检查打印效果。
